This page records DSX Agent Gateway behavior exercised by checked-in tests. It is not a complete Model Context Protocol conformance statement.

## MCP Method Coverage

The direct path sends a request from the entry gateway to a local or static MCP target. The bridge path sends a request through a hub, the DSX Event Bus, and a leaf to a shard gateway.

| Capability | Direct path | Bridge path |
| --- | --- | --- |
| `initialize` | Validated for a sessionful client. | Handled by the hub with stateless capabilities. |
| `ping` | Not separately validated. | Handled by the hub. |
| JSON-RPC notifications | Initialization behavior is regression tested. | Accepted with HTTP `202` and no response body. |
| `tools/list` | Validated with tenant filtering, pagination, and multiple targets. | Validated with one reachable leaf catalog and injected shard selection. |
| `tools/call` | Validated for allowed, denied, unknown, and static targets. | Validated for selected-shard routing and streamed responses. |
| `prompts/list` | Validated with tenant filtering and target prefixes. | Validated through the bridge catalog path. |
| `prompts/get` | Validated with target prefixes and tenant filtering. | Validated with selected-shard routing. |
| Prompt `completion/complete` | Not separately validated. | Validated by bridge unit tests with selected-shard routing. |
| `resources/list` | Validated for supported direct targets. | Not supported by the stateless bridge target. |
| `resources/templates/list` | Validated for supported direct targets. | Not supported by the stateless bridge target. |
| `resources/read` | Validated with a multiplexed target URI. | Not supported by the stateless bridge target. |
| Resource `completion/complete` | Rejected for an unknown multiplexed bridge resource. | Not supported by the stateless bridge. |
| Stateful resource methods | Not separately validated. | Not supported by the stateless bridge. |

Direct resource catalogs remain available when another configured target does not support resources. The gateway omits the unsupported target instead of failing the complete catalog request.

## Catalog and Target Behavior

Multiple targets use a target prefix for tool and prompt names. The published name has the form `<target>_<name>`. Calls with an unprefixed name do not select a default target.

Multiplexed resource identifiers include the target before the resource URI. For example, a target can publish `inventory-mcp+inventory://servers/42`.

The gateway filters catalogs by the authenticated tenant. Unauthenticated requests do not receive target names. An unprivileged tenant cannot discover an operator-only target.

The bridge adds `dsx_bridge_list_shards` to its tool catalog. Callers use this tool to find reachable shard IDs. Bridge tools and prompts require a `shard_id` argument for routed invocation.

## Authentication and Isolation

Functional tests cover the following controls.

- The gateway rejects missing, expired, malformed, and incorrectly issued JSON Web Tokens.
- The gateway validates configured audiences for human, service, and workload identity shapes.
- The gateway derives the tenant from verified claims instead of caller-supplied headers.
- The gateway removes spoofed internal identity and rate-limit headers.
- The gateway forwards the original `Authorization` header to the selected MCP server.
- The gateway separates per-tenant catalogs and rate-limit counters.

The selected MCP server remains responsible for authorizing the forwarded identity within its own domain.

## Availability and Failure Behavior

The local evaluation tests exercise multiple gateway and rate-limit replicas. They also exercise gateway Pod loss, rate-limit service replica loss, Valkey primary loss, bridge hub loss, bridge leaf loss, and NATS outages.

Healthy local targets remain available when a bridge target or remote shard is unavailable. Remote tools disappear from the bridge catalog when no leaf can answer. Calls to an unavailable remote shard return an error instead of routing to a different shard.

The default `FailOpen` rate-limit mode keeps MCP requests available during a rate-limit service or Valkey outage. Rate-limit enforcement resumes after the dependency recovers.

Bridge streaming tests cover early Server-Sent Events delivery, retry of dropped stream replies, cancellation, idle expiry, and graceful leaf drain. The bridge does not repeat an initial routed invocation after an ambiguous missing reply. This behavior prevents automatic replay of side-effecting tool calls.

## Protocol and Observability Coverage

The functional suite validates malformed JSON-RPC input, invalid parameters, unknown sessions, and unknown targets. Regression tests distinguish legacy sessionful behavior from modern stateless requests in the pinned Agentgateway release.

Observability tests cover the following signals.

- Gateway and controller health endpoints.
- Prometheus metric discovery and request metrics.
- Structured access logs without sensitive tool input.
- OpenTelemetry trace propagation through the gateway and bridge.
- Alert rules for missing metrics, synchronization failures, HTTP errors, latency, and authorization failures.

## Validation Environment

These capabilities are validated in the repository's Kind-based local evaluation topology. The topology includes Common Services Cluster and Control Plane Cluster logical sites in one Kind cluster. It is not a production deployment model.

Run the complete repository validation outside the sandbox.

```bash
make test
```

Run the already deployed functional and performance suites with the following target.

```bash
make test-dev
```
